# merged cardio metric_type into interval as the sole cardio-family type

✅ **SHIPPED + LIVE 2026-08-09 (`1379c05`) — merged `cardio` metric_type into `interval` as the sole cardio-family type.** Jake: "having cardio and intervals as 2 separate categories is redundant and intervals should be the only 1" — driven by builder-dropdown clutter, not a missing capability. Confirmed live before building anything: he's **never prescribed varied-length rounds** (every real use is one steady effort or a uniform repeated work/rest pattern — interval's existing `sets_json` block model already covers both), and he wanted to **keep manual/no-timer logging** for the simple case, which plain Cardio had and Intervals-only didn't. **Built:** removed the `Cardio` `<option>` from the builder's exercise-type select (`app-workouts.js`); added a "Steady effort / Repeating" toggle to the interval block editor, **derived** from `sets:1 && cycles:1` plus zero warmup/rest/recovery/cooldown (not a new sets_json key) so the simple case stays as easy to prescribe as plain Cardio was — a fresh block now defaults to Steady (`sets:1,restSecs:0`) instead of the old 8-round HIIT default; new `_isSteadyEffortBlock()` helper (`app-runner.js`) extends the runner's manual LOG button + "+ Add extra set" (previously interval-exclusive-off) to also cover steady-effort blocks, while a genuine multi-round interval still requires the live timer. A legacy unmigrated `metric_type='cardio'` row now correctly auto-selects **and renders** the Intervals editor when reopened, not a label/fields mismatch. **Multi-agent review (3 angles) caught 4 real issues, all fixed same session**: (1) the builder's initial render call still passed the literal `existingType` through, so a legacy row showed "Intervals" selected but the OLD per-set cardio editor underneath; (2) a sibling of the "reads cardio-only `duration` field" bug existed one call-depth deeper in `startIntervalTimer`'s own next-round scheduling, missed by the first fix; (3) `+Add extra set` on a steady block didn't refresh the live timer's phase list, so starting the timer for the added round would have silently ended the exercise one round early; (4) a hand-edited `sets:1/cycles:1` block (not via the toggle) could show "Steady effort" while still carrying nonzero warmup/cooldown — fixed by extracting one shared `_isSteadyIntervalBlock()` predicate the builder and runner both call, checking every field `_expandIntervalBlock` actually turns into a phase, not just sets/cycles. **Live data migration** (`scripts/merge-cardio-into-interval-2026-08-09.sql`) reshaped every real `workout_template_exercises`/`exercises` row from cardio-array-shape to interval-block-shape — read-only check ran first (confirmed the "never varied rounds" claim against every real row, not just memory), full backup table taken before either UPDATE, RLS enabled on the backup per Supabase's own warning (destructive-op + missing-RLS-on-new-table, both correctly flagged). Spot-check after running showed every row correctly reshaped (Assault Bike 10×15s/45s → `workSecs:15,restSecs:45,sets:10`; SkiErg "10km Steady State" → `workDistanceM:10000,sets:1,cycles:1`, etc.) — historical `workout_log_exercises`/`workout_log_sets` deliberately left untouched (every progress/chart read path already treats cardio+interval symmetrically). DB CHECK constraint NOT tightened — `'cardio'` stays DB-allowed (same precedent as `'amrap'`). 9 feature tests (`tests/cardio-interval-merge-2026-08-09.spec.js`), full suite 358 passed / 5 pre-existing `client-workout.spec.js` failures (unchanged baseline) / 1 confirmed flake (unrelated, passed in isolation) / 2 skipped. mobile-checked at 390×844 (Steady and Repeating states, plus the runner's manual-LOG-for-steady-block screen). Explicitly out of scope, flagged not fixed: `saveWorkoutSession`'s separate "Log a past session" modal (its own simpler dropdown, never wrote metric_type, untouched); two unrelated pre-existing bugs surfaced during review — the finish screen over-counts an interval's "sets" by including warmup/cooldown rounds (`app-runner.js:2176,2239`, unlike Progress's `_countableSets` filter which correctly excludes them), and `saveWorkoutSession` never writes `metric_type` for any exercise type. Cache-bust: app-workouts.js/app-runner.js v54→55.
