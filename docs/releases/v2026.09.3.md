## Scope

Two pieces of work, cut together because neither had shipped.

**1. The UX cleanup pass.** Jake walked four areas of the app at phone width off an interactive
selection board and picked 16 items across them — "the app feels slightly clunky in places". One
design doc (`docs/superpowers/specs/2026-09-07-ux-cleanup-design.md`), then built area-by-area, one
commit per area, each behind its own gates.

- **Runner** (R1–R5): the set-complete tick was invisible; the "advance" slot wasn't a button
  pre-first-set; inputs read as disabled; swap/add were bare-text links.
- **Builder** (B1–B5): 5 action buttons ate the first screen; the desktop day grid wrapped 5+2;
  empty days were bordered cards wrapping bordered buttons; the gear icon was unlabelled; the
  periodization bar was a wedged slab.
- **Progress** (P1–P4): four stacked rows of pills before any content; pills wrapped raggedly; Body
  Weight led with an editor instead of data; 1RM rows were cramped at 390px.
- **Dashboards** (D2–D4): the solo bottom nav crammed 7 items; empty test-probe sessions cluttered
  "recent"; the PT stat tiles wrapped 2+1.

**2. The walkthrough batch.** After the cleanup pass, Jake walked the app again and flagged eight
more specific things. Seven shipped here; one (the propagation-prompt interruption model) is its own
piece of work.

**Deliberately out:**
- **D1 — solo/client dashboard convergence.** Structural, ripples into calendar parity and redundant
  1RM displays. Its own session.
- **#5 — deferring the "apply to duplicated sessions?" prompt to the editor's back button.** The
  most-reworked corner of the codebase; needs a full design pass and its own review, not a bolt-on.
- **Drag-and-drop exercise reordering** — still a follow-on, not a replacement for the instant buttons.

## What shipped

### The runner is easier to use one-handed, mid-set

- **The set-complete tick is a visible control.** It was a 44×44 white box with a `color:transparent`
  ✓ — the primary action of the screen rendered as its faintest element. Now: a visible faint tick on
  the incomplete state, an accent border on the current set's row.
- **The "advance" slot is always a real button.** Before the first set it read "Check off a set to
  continue" as centred hint text; now it's a full-width control that, tapped, scrolls to and focuses
  the first empty input.
- **Empty inputs hint the unit** ("kg" / "reps") instead of an em-dash that read as disabled.
- **Swap / Add exercise** are compact outline buttons, not 11px text links crowded under the title.
- **The cross-exercise rest chip** said "Resting `<exercise>` — tap to return", which parsed as if
  the exercise were named "Resting …". Now "Rest for `<exercise>` — tap to go back".
- **"This exercise: 0 reps · last time 21"** stopped showing before you've logged a set — it's a
  beating-last-session gauge with nothing to gauge yet.
- **Copy previous set / + Add new set** are outline pill buttons in both the set editor and the
  runner, not flat accent-coloured text.

### The builder shows fewer buttons and de-clutters empty state

- **The program header is one primary action + a "⋯ Manage" menu** (Edit, Copy to Library, Copy to
  coaching / Move to Personal, Delete) instead of a ragged 5-button block that wrapped to ~5 rows on
  mobile.
- **The desktop day grid puts the whole week on one row** at ≥900px.
- **Empty days lose the card treatment** — just the day label and a slim dashed "+ add" row.
- **The gear icon is a labelled "⚙ Units" pill** on both the runner and builder headers.
- **Periodization status is a chip in the phase header** ("4 weeks · Linear 65→85%"); "Generate
  weeks" stays a top-level button, not a slab.
- **"+ More targets"** now shows a rotating chevron, so it reads as something that expands rather
  than an add-button.
- **"Duplicate week" opens a 1× / 2× / 3× / 4× picker.** Building a 4-week block from a 1-week
  template was 3 taps and 3 waits; it's now 2 taps. Each copy is taken from the source week, not the
  previous copy.

### Progress drops three rows of chrome

- **The Performance tab went from three stacked pill rows to one toolbar** — the sub-tabs on the
  left, the trend range as a compact native `<select>` on the right (shown only for "Per exercise").
- **All the progress pill rows scroll sideways** instead of wrapping — one shared `.chip-row`
  treatment, active pill scrolled into view.
- **Body Weight leads with the data.** Once a starting weight and goal are both set, the big "Weight
  goals" editor collapses to a one-line "Start 90 kg → Goal 82 kg · Edit" summary.
- **1RM rows are half the height** — the date / "estimate from a set" controls hide until you focus
  that lift's value input.

### Dashboards

- **The solo mobile bottom bar is four items + a "More" sheet.** Dashboard / Workouts / Programs /
  Progress on the bar; Library / Calendar / Settings in the sheet. The desktop sidebar still lists
  all seven.
- **"Recent sessions" everywhere drops 0-exercise `workout_logs`** — abandoned starts and test
  probes that showed as "probe · 0 exercises". Display-only; the client + solo dashboards over-fetch
  and filter, the client Workouts history does the same.
- **The coach dashboard's three stat tiles stay 3-up on mobile** instead of wrapping the third onto
  its own row.

### Discard and Delete week actually work now

`window.confirm()` is silently suppressed in embedded browsers (the in-app preview Jake tests in) and
flaky in installed PWAs — the dialog never appears and the call returns `false`, so every
`if (!confirm(...)) return` guard permanently cancelled its own action. **All 20 confirm-gated
destructive actions** — Discard workout, Delete week, Delete program / phase / template / 1RM /
session / event / goal, Generate weeks, Move to Personal, the two invite flows, and the rest — now
use a promise-based `confirmDialog()` DOM modal (title, message, Cancel + a red confirm button, ✕,
backdrop-to-dismiss). It sits above the runner's fullscreen layer, and it can't leave a caller
hanging if it's torn down another way.
