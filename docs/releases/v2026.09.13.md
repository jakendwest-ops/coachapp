## Scope

v2026.09.12 passed the full release gate and was tagged and pushed, but GitHub's "Code quality checks" job failed on it, and
the deploy job has `needs: check`, so nothing deployed. The failing check was not about the release's code. It was
`scripts/check-preview-server.selftest.mjs`, a self-test of the test harness added on 2026-10-01, which fails on GitHub's
Node 22 and passes on the dev machine's Node 24. The check had been red on master since 2026-10-01 (two earlier pushes,
and both v2026.09.12 runs), and nothing alerts anyone when GitHub's checks go red, so it was not noticed until the release
was cut. A release tag is immutable, so the fix ships under a new number.

**In:**
- Everything v2026.09.12 contained. Its notes (`docs/releases/v2026.09.12.md`) are the record of that content: RPE top-set
  autoregulation, the runner's third and fourth walkthrough rounds, the client failed-save rollback (database migration
  already applied to production by Jake on 2026-10-01), the Goals permissions change, the null-session guards in
  `savePerformanceLog` and `saveEvent`, and the security and tooling fixes.
- The CI fix (below).

**Deliberately out:**

## What shipped

Application code: identical to v2026.09.12 (no `js/` or `css/` change in this release).

**The CI fix.** The self-test starts a series of fake web servers and checks that the suite's start-up guard refuses a wrong
or incomplete one. It reused one port for eleven servers in a row. Node 22's built-in HTTP client (undici 6.x) then wrote the
next case's first request onto a keep-alive connection the previous server had just closed and got `ECONNRESET`, reported as
"preview server unreachable" for cases 8, 10 and 12 (the cases immediately after one that made two requests). Node 24
bundles undici 7, which does not do this, so every run on the dev machine passed. Each fake server now gets its own
ephemeral port on 127.0.0.1 and answers `Connection: close`, so there is no connection to reuse.

So the next failure explains itself: `scripts/checks.sh` prints the self-test's whole output (it used to grep for "FAIL"
and re-run the test, which hid the real error for two days), prints the Node version at the top, and the "unreachable"
error now includes the underlying cause. A count in the self-test's final message ("nine" bad servers, really eight) is
corrected.

## Known issues carried into this release

- Everything listed under "Known issues" in the v2026.09.12 notes still applies, including the quarantined
  `pb-consolidation` SOLO write-path test (`docs/bugs/2026-09-30-pb-consolidation-solo-write-path-fails-only-in-the-full-suite.md`,
  open), and the four tests that failed once and passed on retry in v2026.09.12's gate run (`programs.spec.js` duplicate week,
  `progress-trend.spec.js` resting-HR chart, and two in `runner.spec.js`: swap/add exercise and the exercise picker).
- **CI and the dev machine run different Node versions (22 and 24) and nothing pins either.** That mismatch is why a
  Node-22-only failure was invisible locally for two days. Recommended, not done: pin one version (an `.nvmrc` plus
  `engines`, or `node-version` in `.github/workflows/deploy.yml`) so a check cannot pass in one place and fail in the other.
- **Nothing alerts anyone when GitHub's checks go red on master.** Two red runs on 2026-10-01 went unseen. Recommended, not
  done: have `scripts/release.mjs --push` push the branch first and wait for the code-quality job before pushing the tag, so
  a release can never again be tagged without having passed CI.
- The full suite's wall-clock time has grown to 47 to 59 minutes (v2026.09.12's gate: 53.7 minutes).

## Rollback

Code: `git revert v2026.09.12..ee45bae` removes only the CI fix, which would put the red check back and block the next
deploy; to undo the application changes revert the v2026.09.12 range instead (see its notes). Either way, cut and push a new
version, since a pushed tag is immutable. The database migration cannot be undone by a code revert (see the v2026.09.12
notes). Nothing in this release itself writes data in a new shape.
