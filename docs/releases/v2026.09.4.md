## Scope

Jake walked the live v2026.09.3 build and flagged eight things. Four small, self-contained UI fixes
ship here. The other two — the propagation prompt firing per-edit instead of once on exit, and
"unilateral" being a mutually-exclusive Type option rather than a modifier on weight-and-reps — each
turned out to be a subsystem change (the first entangles six functions and five test files, the
second needs a `metric_type` migration), so they're deferred to their own spec sessions.

**In:**
- The dashboard Weight tile lands on Body Weight, not "wherever you last were" in Progress.
- The runner's cross-exercise rest chip reads as a sentence instead of "Rest for `<name>`".
- "Copy previous set" / "+ Add new set" are equal width and centred, in the set editor and the runner.
- The add/edit-exercise modal is denser; a builder day slot's preview opens full-width instead of
  crammed into a 1/7-width column.

**Deliberately out:**
- **#4 — propagation prompt once on exit.** Needs a written spec; the current chain
  (`_checkClientPlanPropagation` → … → `_applyToAllSessions`) is built around one change object and
  ends every path with an `openTemplate()` repaint.
- **#8 — unilateral as a modifier.** `metric_type = 'unilateral'` is stored and read across the
  runner, builder, session detail and reps charting — a data-model change with a migration.

## What shipped

**The Weight tile lands on Body Weight.** `window._progressTab` persists for the SPA session, so if
you'd last opened Benchmarks, the dashboard's Weight tile took you back there. The three dashboard
links into Progress now name their target tab (Weight → Body Weight, "+N more" → Benchmarks).

**The rest chip is a sentence.** When you've moved to a new exercise but an earlier one's rest timer
is still counting, the chip said *"Rest for Chest Supported Machine Row — tap to go back"*, which
parsed as if the exercise were named "Resting …". It now reads *"Chest Supported Machine Row —
`1:23` rest left · tap to return"*, with the live countdown merged into the sentence.

**Equal-width set buttons.** "Copy previous set" and "+ Add new set" were auto-width (different
lengths) and left-aligned. Now equal width (capped at 180px) and centred under the panel — in both
the template set editor and the runner.

**The exercise editor is tighter.** The add/edit-exercise modal was 560px wide with 8–16px padding
on every target row. Now 480px, rows and set-card headers tightened, and the superset helper trimmed
to "(same letter links exercises)".

**A builder day slot's preview opens full-width.** The week grid is seven equal columns, so an
expanded slot crammed six exercises + prescriptions + Edit/Remove/Save-to-Library into a ~130px
column while the other six columns sat empty beside it. Tapping a slot now opens a full-width
preview panel **below** the grid; Edit / Remove / Save to Library are one equal-width row.
`_toggleBuilderSlot` re-renders the week from the cache already held by `loadAllPhaseWorkouts` — no
refetch — and the open slot's id lives on `window` so it survives that re-render.
