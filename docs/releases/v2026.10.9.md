## What shipped

Plain English first. **In the gym:** if the signal drops while you save, tap Save again and you get one complete workout —
never two, never an empty one. If it still cannot save, your workout stays on the phone and a bar on every page says
"Workout not saved" with Retry and Discard, for up to 14 days, so a workout that failed in a basement gym can be saved the next
day. Discard checks first: if the workout had in fact saved, nothing is deleted; with no signal it keeps the workout. Signing
out asks first when a workout is not saved yet. On a shared phone, another person's unsaved workout is never shown to you,
discarded or overwritten. **For coaches:** booking a client's next block no longer replaces the running one on their screens, and a client's weekly
check-in now lands on the coach's Home to be marked Seen or answered — the client sees both.

Technical (R4a):
- `js/app-runner.js`: `_persistSession` is the one writer for both save paths. The session id is chosen on the phone
  (`crypto.randomUUID()`, before the first await, kept in the draft); every exercise and set id is derived from it
  (`_stableUuid`, `js/app-core.js`). Writes are `upsert(..., { onConflict: 'id', ignoreDuplicates: true })`; a rename between
  attempts is applied by an update (a client account cannot update its own session, so it is told instead); then two head-only
  counts of exactly the rows written — a skipped row that is not ours fails, never "saved". The old compensating deletes are gone.
- The pending draft: `pendingSave`, `saveLogId`, `saveWritesStarted`, the typed name and notes, `userId`; `_loadRunnerDraft`
  keeps a pending draft 14 days and hides another account's; `launchRunner` and `_saveRunnerDraft` refuse to write over it.
- `_removePartialSave` / `_discardPartialSave`: Discard reads the session first and deletes only a set-less (partial) one,
  children first, checking each delete's rows.
- The bar (`_refreshPendingSaveBar`, redrawn on every navigation; removed by `showAuth`), Retry reopens the finish screen.
  `signOutAndClearDrafts({ ask })` asks first and counts every account's unsaved workouts. The manual form locks its rows after a
  failed save and tidies on ✕ / Cancel (`closeLogSessionModal`).
- `css/main.css`: the bar, clear of the bottom nav and the master account's view switcher. Module versions: app-core 51,
  app-runner 125, app-progress 89, main.css 41.
- Test helper `tests/fault.js` — the suite's first fault injection (abort, lost reply after the server committed, 500, fake
  success).

Technical (check-in loop): see `77407fd`'s message and its ledger row — `js/app-dashboard.js` (the Home list), `js/app-clients.js`
(Overview Seen / Reply), the client form, `types/database.d.ts` regenerated, and `scripts/sql-verify/checkin-review.*` (a local
verifier, now in `checks.sh`).

Technical (current plan): see `fcf2b15`'s message and its ledger row — `_currentAssignment` in `js/app-core.js`,

## Rollback

Tag `v2026.10.8`'s commit and push it, or revert the range. R4a stores nothing in a new shape on the server (ordinary rows, with
ids chosen by the phone); a phone holding a pending draft from this release keeps it harmlessly under the previous version, which
then applies its same-day rule. The current-plan view change is backward-compatible with v2026.10.8's code, so it can stay. The check-in columns, policies and trigger stay in the database on a rollback; whether v2026.10.8's code updates any other
