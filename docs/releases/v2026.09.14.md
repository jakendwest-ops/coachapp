## Scope

Three notes from Jake, built in order and each approved by him before it was built: the 2026-10-03 note (no grey "ghost" numbers on an RPE
top-set exercise; the runner's Stats sheet should show as much as My progress and agree with it; the whole mobile dashboard reworked as a
landing page and hub) and the 2026-10-04 note (a collapse/expand button on the My progress exercise cards; the Workouts "Up next" card
should name the next workout; the runner's "Last time" panel should show the top set). The program-page redesign and an RPE option for
periodization from the same 2026-10-04 note are scoped and have a prototype, and are NOT in this release.

**In:**
- RPE top-set exercises take no grey placeholder numbers from last session (the boxes fill in once the top set is ticked).
- One exercise stats card, shared by the runner's Stats sheet and the My progress exercise cards: one set of maths, one paged read of the
  whole history, records named by the SET ("Heaviest set 117.5 kg × 3"), and an estimated 1RM that says which set it came from.
- The dashboard rework: one landing-page design for the personal, coached-client and coach dashboards (a Today card, the week as a tappable
  strip, a streak of weeks that hit the whole plan, a program tile, body weight, calendar and goals; the coach's version shows what clients
  have logged). Solo and client now share one loader.
- My progress, Per exercise: cards start folded, open with a tap, with a Collapse all / Expand all button; only open cards draw a chart.
- The Workouts "Up next" card names the workout (today's session while it is not logged, otherwise the next planned one) and says Today or
  the date; "Program complete" when nothing is left. Program weeks are counted Monday to Sunday like the calendar (the dashboard tile used
  to count from the start date).
- The runner's "Last time" panel shows the top set ("Top set 23 kg × 5", with the RPE or RIR if one was logged).

**Deliberately out:**
- The program-page redesign and the RPE periodization method (scoped, prototype up, not built).
- The coach's "2 of 5 done" (needs a new database view; SQL for Jake to run, offered as a follow-up).
- Matching a logged session to its planned slot for "Up next" (a swapped order can still name a workout already done; offered, not built).
- The runner stamping each session with the UTC day instead of the local day (filed, not fixed: it changes saved data).

## What shipped

Plain English first. **Workout screen:** the grey old-session numbers on a top-set exercise are gone; the Stats button now opens the same
detailed page My progress has, so the figures match, and the "Last time" box says "Top set 23 kg × 5" instead of "2 sets, top 23 kg".
**My progress:** each exercise is a one-line card (name and best set) you tap to open, with one button to open or close them all; the page
is quicker because only open cards draw a chart. **Workouts:** "Up next" says which workout ("Upper Body"), and when, and moves on once you
have logged it; before, it kept pointing at the first workout of the week. **Dashboard:** every role lands on the same kind of page, with
today's session first.

Technical detail is in `docs/decisions.md` (the 2026-10-03 and 2026-10-04 entries) and the bug rows listed there. In short: `_mountExerciseStats`
(app-progress) draws the shared card from `_xsSessionMetrics` / `_xsRecords` and the paged read `_fetchExerciseSessions`; app-dashboard.js is
rewritten around `_dashLoadOwn`, `_dashStreakWeeks`, `_dashWeekDays`, `_dashProgramInfo`, `_dashNextSession`; the fold-up list is `_perfShell` /
`_perfToggle` / `_perfAll` with open state in `window._trendState.open`; `fetchRunnerLastSession` now also selects each set's `phase`;
`_programWorkoutsByDate` also records each session's phase and week. Cache-busting versions: app-dashboard 30, app-progress 76, app-runner 113,
app-workouts 145, app-calendar-goals 30, main.css 26.

## Known issues carried into this release

- The runner files a session under the UTC day, not the local day (`docs/bugs/2026-10-04-runner-saves-the-session-date-as-the-utc-day.md`):
  harmless for a UK user except between midnight and 1 am in summer; wrong in the evenings for anyone west of UTC. No such user today.
- "Up next" follows the calendar: a workout done on another day or in a swapped order is not matched to its slot, and a two-a-day day counts
  as done once anything is logged (`docs/bugs/2026-10-04-workouts-up-next-card-does-not-name-the-workout.md`).
- None of the new screens has been looked at on Jake's phone with his real data; they were tested with example data and the test accounts.
- Carried from the pre-push review (all non-blocking): the coach "Goals due soon" read is scoped by database permissions alone (unchanged from the page it replaced); raw uuids in the Up next button's handler; the Stats sheet matches history by exercise name while Last time matches by id first; dead code left by the dashboard rework. "View as client" works only on the dashboard (`docs/bugs/2026-10-04-view-as-client-only-works-on-the-dashboard.md`).
- Open from earlier and unchanged: Sign out ends every device's session; CI runs Node 22 while the dev machine runs Node 24.
