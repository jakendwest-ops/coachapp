## What shipped

**A dropped connection can no longer leave a client with half a programme, or none.**
- **Before:** assigning a programme ran from the browser as a chain of separate writes. It archived the old block (on
  restart), deleted the old assignment, swept its copies, inserted the new assignment, then copied every session one request
  at a time. A 12-week, 4-session programme was ~97 requests in a row. A dropped connection or a refused write part-way left
  permanent partial state; a restart could delete the client's plan and never insert the new one. The code reported this, but
  could not prevent it.
- **Now:** both assign buttons call one Postgres function, `assign_program()`
  (`scripts/add-assign-program-rpc-2026-09-27.sql`), which does all of it in a single transaction. Either everything lands or
  nothing does.
- **Security:** it runs with the caller's own rights (`security invoker`), so every read and write still passes the live
  row-level-security policies. It only adds checks. Only signed-in users can execute it.
- **Deliberate behaviour changes**, all towards "change nothing rather than half":
  - a session whose workout can't be read now fails the whole assign (the old code kept a half-copied plan);
  - a failure cleaning up the old copies now aborts a restart (the old code carried on and leaked them);
  - two tabs restarting the same plan at once: the second is told it "was just changed elsewhere".

**Signing out on a phone now wipes in-progress workout drafts.**
- **Before:** the 2026-07-10 fix that clears drafts (client name, exercises, weights) at sign-out was wired only to the
  desktop sidebar button, which phones hide. Phone users sign out from Settings, so the fix never ran on the shared gym devices
  it was written for.
- **Now:** all four sign-out routes go through one helper, and `checks.sh` rule 9q refuses any other sign-out call.

**Smaller fixes.**
- **"PT" pill:** it now appears only for the master account; every phone user used to see it.
- **Login placeholder:** repaired; it showed `â€¢â€¢…`.
- **Third-party scripts:**
  - supabase-js 2.117.2 and Chart.js 4.5.1 (what `@2` and `@4` resolved to that day, so nothing that loads changed) are pinned
    with sha384 integrity hashes;
  - `checks.sh` rule 9p refuses a floating or unhashed third-party script;
  - before this, an upstream release could change production with no tag.

## Database changes

- `scripts/add-assign-program-rpc-2026-09-27.sql`: the `assign_program(uuid, uuid, date, boolean)` function.
  - Applied live by Jake on 2026-09-27, then re-applied the same day with two review fixes (the two-tab race errcode and a
    foreign-key read-back).
  - Read-back after the second apply:
    - `security_definer=false; config=search_path=public, pg_temp`;
    - `anon` execute `false`, `authenticated` `true`;
    - exactly four foreign keys point into `workout_templates`, each CASCADE or SET NULL: `client_program_workouts`,
      `program_phase_workouts`, `workout_logs`, `workout_template_exercises`.
    - These are the same four the local verifier models, so the restart's sweep cannot be blocked by a foreign key.
  - Additive. Rollback is `drop function public.assign_program(uuid, uuid, date, boolean);`, but roll back this release's JS
    first, because the app now depends on the function.

## Known issues carried into this release

- `deleteProgram` and `deletePhaseWeek` are still browser-side chains (next release).
- **`_cloneProgramForClient` has no app caller.** Four older specs still call it directly; retire it with them.
- **A workout copy can lose its "trained from" link on restart, in one narrow case:** a client moved to another coach, trained
  there, and then moved back. Row security hides the other coach's log, so the copy is swept and the log's `template_id` is
  set to null; the log itself survives. The old JS behaved identically. Fixing it needs a wider read policy, which is a
  separate decision.
- **New bug file, `2026-09-27-sign-out-during-boot-can-leak-master-flags-to-next-account`:** a narrow UI race, still open.
  Row security still guards the data.
- **Accepted residual of the sign-out fix:** a workout running in a *second* tab rewrites its draft within 10 s of a sign-out
  (documented in its bug file).
- Everything in v2026.09.8's own list, unchanged.
