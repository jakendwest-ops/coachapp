# v2026.09.11 — The workout runner rebuilt around logging sets: tabs that show what's done, a Next that goes to what's still to do, and a tappable Stats sheet

**Cut:** 2026-09-28
**Commits:** `8a0a631..657e912` (2), plus this notes commit
**Previous release:** v2026.09.10

---

## Scope

Jake walked through the workout runner on his phone on 2026-09-28 and sent eight notes with screenshots. The main
complaint was "the UI on this page is not user friendly": measured on a phone, the first set to type into began 252px
below the exercise tabs, under a Swap/Add row, a stats card and three prescription boxes. Everything in this release
answers those eight notes. It is client-side JavaScript and tests only.

**In:**
1. The program day list (client Workouts page, and the coach's client Programs tab) says the weekday: "MONDAY · DAY 1",
   with the session name underneath, instead of "DAY 1 / DAY 3 / DAY 5".
2. The runner's Back button is gone; the numbered tabs go back.
3. The exercise name is shown in full: it fits at full size once Back is gone, and a name that still would not fit shrinks a
   pixel at a time (down to 15px) instead of being cut off with an ellipsis.
4. "Next exercise" goes to what is still to do, not to the next number. Skip from 1 to 3, finish 3, and it returns to 2.
5. A tab is green when every set of that exercise is done, purple only for the one on screen, plain otherwise (it used to
   go light purple for any lower number, so a skipped exercise looked done).
6. "Beat it" is gone from the last-session heading.
7. The "log-first" layout: the set table now starts about 50px under the tabs. Swap, Add and Units are behind a "⋯" button;
   the prescription is one line under the title; a bar at the bottom is always there (Skip exercise / Next exercise /
   Finish) and names the exercise it goes to.
8. A "Last time" line under the table with a filled **Stats** button opens a sheet: last session's sets, today against last
   time, a progress chart (Top set, Est. 1RM or Volume) and the heaviest lift ever.

**Deliberately out:**
- Six further notes Jake sent the same day are not built (see "Known issues"): template-builder Edit/Remove buttons, the
  interval "Initial countdown" format, and four solo-dashboard changes.
- The Stats sheet is for weight × reps exercises that have a previous session — the same gate the old stats card had.
  Cardio and interval screens keep their own controls and get only the new header.

## What shipped

**Tabs and Next (items 4, 5).** The runner used to know an exercise only by its position: a tab was light purple if its number
was lower than the current one, and Next was a bare `exIdx++`. `_isExerciseComplete` now says an exercise is complete when
every one of its sets is done (an interval block counts its work rounds only, through the same `_countableSets` filter the
finish screen and My Progress use). `_nextExerciseTarget` decides where Next goes: **from a finished exercise, the lowest one
still to do; from an unfinished one, the next unfinished one ahead of it, or Finish if there is none.** Every place that says
"next" — the button, the "Next:" text, both rest bars and the cardio/interval auto-advance — asks that one function. A
first version wrapped round to the start and would have cycled for ever when every exercise was half done; a reviewer found
it before it shipped.

**The log-first layout (item 7).** Swap, Add and Units moved into a sheet opened by a 44px "⋯" button (it uses the app's
existing bottom-sheet `.modal-overlay`; the app has no dropdown precedent). The prescription is one line (`#wr-rx`),
rendered by the same `_renderTargetBarHtml`, so the escaping test that guards it still guards the real sink. The bottom bar
(`#wr-cta`) replaces a dashed "Log a set to continue" placeholder that left an exercise you could not do with no way
forward: an untouched exercise now reads "Skip exercise". An untouched **last** exercise reads a neutral "Finish workout"
and goes through the End button's own flow, because a green Finish there let one mis-tap end the session and the finish
screen has no route back to the runner.

**The Stats sheet (item 8).** History is the client's last 60 workouts, narrowed to that one exercise, newest 12 sessions —
inside the API's 200-row cap by construction. The chart reuses the Progress page's `_renderMetricChart`, with a dashed
"Today" point once a set is ticked. A failed read shows "Couldn't load your progress" with Try again; a bodyweight exercise
says it has no logged weight; a missing Chart.js says so, and the ✕ still closes the sheet. A running rest timer is
untouched while the sheet is open.

**Name, day list, wording (items 1, 3, 6).** See "In" above. The weekday label is one shared `_dayHeadingLabel`, coerced to a
number before it reaches HTML.

**Defects a fresh-eyes review found in the first builds, fixed before this release** (each pinned by a test that fails when
its fix is removed): interval warm-up and cool-down were counted as finished rounds; every switch of the chart measure left a
Chart.js instance behind; closing the sheet destroyed the chart before removing it, so a throw could strand a full-screen
sheet over a live workout; "25 Sept" would have read as the 24th anywhere west of UTC; pound values needed converting, not
concatenating; a bodyweight lift would have said "after a couple of workouts" for ever; the "⋯" was under the 44px touch
target.

## Known issues carried into this release

- **Six notes from Jake, same day, not built.** Template builder: the Edit and Remove buttons are too big and squeeze the set
  text ([ledger](../bugs/2026-09-28-template-builder-edit-and-remove-buttons-squeeze-the-set-text.md)); the interval "Initial
  countdown" should read `0:00` like its neighbours
  ([ledger](../bugs/2026-09-28-interval-initial-countdown-is-the-only-time-field-not-in-0-00-format.md)). Solo dashboard: rename
  "Next up" to "My calendar"; replace the Benchmarks card with a "My progress" tile; merge the "Current program" strip with the
  next-session tile; and a question about Goals — a `goals` page exists but is only reachable from a dashboard tile, so it
  needs Jake's decision.
- **Behaviour change worth knowing:** Next no longer means "the next number". After a finished exercise it returns to the
  lowest one still to do, including one you deliberately skipped. An exercise with no sets logged has a "Skip exercise" bar,
  so a skipped one can be skipped again; the red End button still ends the workout.
- **`progress-trend.spec.js:5` fails intermittently** — the same rate with the previous runner file (1 of 48 vs 2 of 48), so
  it is not from this release ([ledger](../bugs/2026-09-28-progress-trend-resting-hr-chart-test-fails-intermittently.md)).
- **The login helper's 10-second `#auth-screen` wait times out now and then**
  ([ledger](../bugs/2026-09-26-ownworkout-teardown-can-leave-a-template-behind-and-fail-the-hygiene-test-for-two-hours.md)).
- `_setExercisePickerButtonsDisabled` (app-workouts.js) is now inert: the Swap/Add buttons it disables only exist while the "⋯"
  menu is open. Harmless; the picker's real double-open guard (a synchronous "is a picker open" check) is unchanged and tested.
- INFERRED, not observed: a legacy template exercise that has `reps`/`weight_kg` but an empty `sets_json` would have lost the
  old "8 reps @ 60 kg" header line in table mode. No such rows were found.
- **From the confirmatory review, minor and not acted on** (changing code after review would have put the released code out
  of step with what was reviewed): destroyed Stats-sheet charts stay in the shared `_activeCharts` list until the next
  dashboard render clears it (a few KB, bounded); the "chart could not be drawn" fallback is untested and does not destroy a
  half-built chart first (very rare); there is no test for a MIXED history (some bodyweight sessions, some weighted) or for
  exactly one weighted session plus today; and "Finish workout" on an untouched last exercise with nothing logged anywhere
  discards the session on one tap with no confirm — exactly what End does today, and only unticked typed values and the notes
  box would be lost.
- The bug row `2026-09-28-runner-tabs-show-position-not-completion-and-next-exercise-cannot-return-to-a-skipped-one` is
  `fixed-awaiting-jake`: it closes when Jake confirms it in the live app.
