## What shipped

**Editing a workout template and then immediately navigating away could, rarely, bring the editor back
without warning.** After saving a plain (non-programme, non-client) template, the app kicks off a background
check for other sessions sharing that template's name — if there's nothing to propagate, it silently
re-opens the same template to refresh the screen. That background call was never cancelled if you'd already
clicked away to a different page in the meantime; when it finally finished, it would paint the template
editor back over whatever you were now looking at, with no warning. Fixed: the editor now notices when the
app has moved on while it was loading, and refuses to repaint. Proven with a test that reproduces the exact
race (delays the background call, navigates away, confirms the old page survives), checked red with the fix
removed and green with it restored. **Not confirmed to be Jake's original 2026-08-07 "the edit doesn't save
until I refresh" report** — that report's exact repro (three cardio sessions inside a programme) takes a
different, already-awaited code path that already tests clean. This is a real defect found on the same
screen, filed as its own fix; the original row stays open until Jake reproduces his edit live once more.

**A client's Goals page could throw an error instead of navigating.** `backToGoals` assumed its container
always existed; if it didn't — a role switch or navigation mid-load — the next click threw instead of
landing anywhere. Now it falls back to the Workouts page (chosen because it's the only page valid for
coach, client, and solo accounts alike). Proven for both the coach and solo paths that can reach this
function.

**A subagent could route around the ownership/RLS review gate by switching tools.** The gate that blocks an
unreviewed ownership-related commit was only wired to fire on the Bash tool; a commit sent through PowerShell
never reached it at all, whatever it would have decided. One incident of exactly this happened. Fixed by
widening the trigger to both tools, proven live and with a permanent regression test.

**Releasing is faster and the bug ledger is far more honest.** A push used to run the full browser suite
(~7 minutes); it now runs static checks only (~51 seconds), because `release.mjs` already runs the full
suite before every tag — master can carry a browser regression for a few hours between releases, but nothing
reaches production without the full suite. Cutting a release used to be four manual steps; it's now one
command that also refuses to tag anything that changed after the suite ran. Separately, ~92 of the ~193 bug
files were reconciled: rows Jake had already accepted as fixed moved out of the everyday list, and rows with
a real red-before/green-after test on record were closed outright — the ledger had drifted well behind what
was actually true of the code.

**A ledger row can no longer sit open forever with no way to close it.** Measured on 2026-08-29: 70% of open
bug rows said nothing that could ever prove them done. `os-lint` now refuses a *newly filed* row with no
stated closing condition (the existing backlog of 27 such rows is grandfathered, not retroactively blocked).
