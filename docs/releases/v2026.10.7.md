**Cut:** 2026-10-28
**Commits:** `v2026.10.6..` the release commit: the sound-engine rebuild (`8ce067a`), the exercise builder rework, the notes commits and the five new ledger rows from Jake's 2026-10-28 requests
**Previous release:** v2026.10.6 (2026-10-25, live)

## Scope

Two things from Jake on 2026-10-27 and 2026-10-28.

**1. The beeps** (a bug). They worked for the first two exercises of his gym session and were never heard again. He confirmed he had left Safari (to change the music) when they stopped, and that they neither continued nor came back when he returned. Measured on his iPhone (iOS 18.7) with the Sound recovery test page on 2026-10-28, twice.

**2. The exercise builder** (four requests, one rework): make the workout page and the Set targets part of the Edit exercise modal easier to use; give back-off sets a clear choice between a percentage of the **weight lifted on the top set** and a percentage of the **estimated 1RM** with few taps; and replace the "↑" copy button that "only makes sense to me because I know what it means". Jake saw a tappable prototype and said it was "looking much better" before it was built.

**In, the beeps:**
- **The sound engine is replaced when it can no longer be trusted.** iOS stops the engine's clock when Safari is left, while the engine still says "running" (or "interrupted") and every beep goes nowhere. Waking it with `resume()` does not bring it back; a new engine does. The runner now notes when the page is hidden and, at the next tap (the tap that logs a set or starts a timer), closes the old engine and builds and starts a new one before the rest begins. It does the same for an engine that says "interrupted" or "closed", and as a backup for one that says "running" while its own clock has barely moved over three seconds or more. A tap ANYWHERE while the runner is open also rebuilds a stale engine (the get-ready count-in, the interval timer and the set-timer overlay have no button that does it). The rest timer itself never rebuilds anything: a new engine only starts from a tap.
- This replaces the "wake an interrupted engine" step shipped in v2026.10.6, which the phone tests showed does not work.

**In, the builder:**
- **Sets that match are edited as one group.** A weight-and-reps exercise opens on "How are the sets set up?" with two buttons, **Straight sets** and **Top set + back-offs**, a **number-of-sets stepper**, and one row of fields (reps, rest, effort, weight) that applies to every set in the group. **Customise each set** opens the old per-set cards. They also open on their own when the saved sets already differ (an existing template with a drop set), with a note and a "Make every set the same as set N" button; a difference is never hidden, and nothing is flattened without a tap.
- **"% of" has three plain choices**, in a dropdown on the back-off sets: **Today's top set weight** (new), **Today's estimated 1RM** (what "Today's top set" always meant: the 1RM worked out from the top set's weight, reps and RPE), and **Last saved 1RM**. Under it, one sentence says what the choice means, and a **worked example** the coach can type a top set weight into shows the answer for the percentage they entered (for example, a 100 kg × 4 @ RPE 7 top set at 70%: 70 kg of the weight, 85 kg of the estimated 1RM, 82.5 kg of a saved 1RM of 120 kg, rounded down to 2.5 kg as in the runner). Choosing Top set + back-offs makes the first back-off set for you, already pointed at the top set weight, because that needs no effort and no saved 1RM.
- **The runner understands the new choice.** `intensityBasis: 'topSetWeight'` takes the percentage of the weight actually lifted on the (ticked) top set; no RPE is needed. `'topSet'` keeps its meaning, so no saved template changes.
- **AMRAP and bodyweight stay visible switches** (Jake's 2026-08-14 rule): "Last set: as many reps as possible" and "Bodyweight exercise", in both the group view and the per-set cards.
- **The copy-from-above button says what it does:** "Same as set 1" instead of "↑".
- **The workout page:** each exercise is one card with a short summary ("3 × 5–8 reps · RPE 8 · 2:00 rest"; a top set reads "Top set · 4 reps · RPE 7" then "then 3 × 8 reps · 70%"), and the **whole card is the Edit button**. **Remove moved into the editor**, and the page shows "Removed X · Undo" for 8 seconds afterwards. **Reorder** is a mode with arrows instead of arrows on every card, and **+ Add exercise** sits after the list.
- Every toggle pill (AMRAP, BW, TOP SET and so on) now exposes its on/off state to screen readers (`aria-pressed`); before, it was colour only.

**Deliberately out:**
- A rest already running when you switch to Spotify and come back stays silent until your first touch of the screen, because a rebuilt engine only starts from a tap. A "Tap to turn beeps back on" message for that case needs Jake's go-ahead first, and a second test round ("Rebuild by itself" on the test page) would show whether the page can do it with no tap at all.
- Voices. Every spoken cue pauses Spotify on iOS 18 (the original bug). Jake chose beeps.
- **Dark mode by default** (Jake: "I also prefer the dark mode, could we make that the default across the app"). Filed, investigated, not built; it waits for his go.
- Other exercise types (timed hold, jump, intervals) keep their existing per-set cards; the grouped view is for weight-and-reps and unilateral.
- Periodization: the weekly percentage wave leaves both top-set bases alone, as Jake decided for `'topSet'` on 2026-10-01 (`tests-node/periodization-basis.test.mjs`); the new `'topSetWeight'` follows the same rule, so a periodised programme never turns "70% of the top set" into a load nobody chose.

## What shipped

Plain English first. If you leave Safari during a workout (to change a song, answer a message, or lock the phone) and come back, the beeps now work again from your next tap. What you give up: if you are in the middle of a rest when you switch away, that one rest's beeps are lost.

Building a workout is now: tap the exercise, say whether it is straight sets or a top set with back-offs, set how many sets, type the reps and rest once, and (for back-offs) pick what the percentage is of and see the kilos it gives. The page is a short list you tap, with Undo if you remove one by mistake.

Technical:
- `js/app-runner.js`: `_noteAudioHidden`, `_audioLooksDead`, `_rebuildAudio`, `_newAudioCtx`, `_audioTapUnlock`; `_unlockAudio(fromTap = true)` rebuilds on a stale, closed, interrupted or frozen engine and starts the new one inside the tap, and only the tap form may rebuild; `_restTick` uses `_unlockAudio(false)`. Builder side: `_recomputeLiveE1RM` also records `ex._liveTopWeight` (the ticked top set's weight); `_basisKgFor(ex, tgt)` picks the number a back-off percentage is taken of; the basis label and the "log the top set first" note follow the basis.
- `js/app-core.js`: `_isTopSetBasis`, `_intensityBasisOrDefault`, `_intensityBasisShort`, `_intensityBasisLabel`, `_intensityBasisHelp` (one home for the three basis names and their wording).
- `js/app-programs.js`: the periodization helpers and the held-count line use `_isTopSetBasis`, so both top-set bases are treated alike.
- `js/app-workouts.js`: the grouped editor (`_tsGroupUniform`, `_tsPropagate`, `tsSetStructure`, `tsStep`, `tsShowEachSet`, `tsMakeSetsSame`, `tsToggleLastAmrap`, `tsToggleAllBodyweight`, `tsBasisChanged`, `tsExampleRefresh`, `_tsStructureHtml`, `_tsGroupedHtml`, `_tsExampleHtml`); `flushTemplateSets` copies a group's first set onto the rest only while the grouped view is on screen (`dataset.tsView`); the page (`_tplExerciseLines`, `_tplCardHtml`, `_toggleTemplateReorder`, `_tplUndoHtml`, `_undoRemoveExercise`, `_dismissRemovedExercise`); `_cleanTemplateSets` saves `'topSetWeight'`; `_togPill` gains `aria-pressed`.
- `css/main.css`: the builder block (`.wb-*`, `.tpl-*`), tokens only.
- Module versions: app-core 46, app-programs 78, app-workouts 151, app-runner 123, main.css 39.

## Database changes

None. `sets_json` is unvalidated JSONB: `intensityBasis` gains a third value, absent or unknown values read as `'stored'`, and `'topSet'` rows mean what they always did.

## Rollback

Tag `v2026.10.6`'s commit and push it, or revert the range. Nothing in this release changes stored data or the database. Templates saved with the new basis (`'topSetWeight'`) are read by the previous version as "stored 1RM" (its default for an unknown value), so rolling back after a coach has used the new choice makes those back-off sets use a saved 1RM until they are edited.
