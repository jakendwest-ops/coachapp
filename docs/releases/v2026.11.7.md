## What shipped

- **Supersets in the builder.** "Add + superset" adds the next exercise as its partner, which gives A1/A2 tags (up to A3). Sets are
  set once for the whole superset. "Remove from superset" splits a pair back into two normal exercises. The typed "Superset group"
  box is gone. The stored data is the same as before (`superset_group` on each row).
- **Supersets in the logger.** One exercise at a time, round by round: "Superset A · round n of N", with the rest coming after the
  round, not after each exercise.
- **Schedule one of your own workouts on a day** (Personal view):
  - "Add to calendar" on your own rows in Workouts.
  - "+ Add a workout" on a calendar day and on a rest day. It replaces "Train anyway"; clients keep "Log a workout".
  - An added workout counts as planned everywhere a plan session does: Today with its own ▶ Start, the week strip, done or
    missed, and the calendar (shown with a "+" and an "Added" badge). "Remove from this day" takes it off and keeps the workout.
  - Technical: an `events` row with `template_id`. `_scheduledByDate` and `_mergePlanned` (app-calendar-goals.js) turn these rows
    into plan-shaped sessions in the dashboard's `progByDate` and the calendar's maps. The dashboard's ordinary events read now
    excludes them (`.is('template_id', null)`).

## Database changes

`scripts/add-event-workout-link-2026-11-16.sql`, applied by Jake **BEFORE** this code (2026-11-16). It adds:
- the `events.template_id` column, with ON DELETE CASCADE to `workout_templates`;
- a partial index on that column;
- the `events_guard_template` trigger. It allows a signed-in user only their own Personal-library workout, on their own Personal
  record, with `created_by` set to themselves.

The previous live code never reads the column, so it runs fine with the column in place. Verified on PGlite: 38/38 checks, and all
15 mutations caught.
