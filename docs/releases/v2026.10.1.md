## Scope

Jake's three runner reports of 2026-10-11 (a 0 weight, "are you sure" on Finish and End with a way back from the finish page, and the post-session
1RM list that should ask first), built and tested as he answered them ("0 should be logged as 0, and there should be a back to workout button").
They rode on a small periodization fix and some tooling that were already on master. This is the first release with the month number 10: the
scheme is year.month.sequence, so the sequence restarts.

**In:**
- **A weight of 0 is logged, shown and remembered like any other.** Bodyweight work (dips, pull-ups) is logged at 0 kg. The database already held
  the 0; what dropped it was every place that SHOWS or REMEMBERS a weight with a truthy test: the grey number in the next session, the finish
  screen, the wizard's set list, the "Beat" strip, and the Stats sheet.
- **Finish workout and End ask first** ("Finish this workout? You can still go back and change it from the next screen"; with nothing logged,
  End says so). The finish screen has a "Back to workout" link; going back keeps the logged sets, the name and notes typed, and is refused while
  a save is under way.
- **The new-1RM estimate asks first.** After a session that points to a new estimated 1RM, one short question appears ("Workout saved. Your session
  points to a new estimated 1RM. Do you want to view or update it now?" - View / Not now). The full list opens only on View. Not now goes on to the
  Workouts page and saves nothing. If the page changes while the question is open, it does not route on a second time.
- **Periodization save checks every write** (`savePeriodizationConfig`): a refused tier or phase update (RLS answers 200 and an empty list) is
  now an error message, not a silent success, and the tier write is anchored on the verified phase.
- **Tooling:** CI runs Node 24 like the dev machine; `scripts/verify-live.mjs <tag>` compares every file the live site serves with the tag, byte for
  byte; the self-tests ignore inherited `GIT_*` variables; the resting-HR chart test is de-flaked.
- Docs: a root `README.md`; the over-budget docs archived verbatim; the Vault-severing session guard.

**Deliberately out:**
- Prescribed (coach-set) 0 weights in the workout editor (`app-workouts.js` and two runner lines): not a real case today; a new ratchet in
  `scripts/count-baseline.json` pins the count so it cannot grow (`docs/technical-debt.md`).
- The "session on an unscheduled day was not remembered" report: not reproduced as a save problem (see below); its row stays open.
- Sign out ending every device's session: still waiting on Jake's call.

## What shipped

Plain English first. **Logging 0 kg now works like any other number:** type 0, tick the set, and it shows as "0 kg × 9 reps" on the finish screen,
is the grey suggestion in the box next time, and appears in "Last time" and in the Stats sheet's history ("0×9 · 0×6"). The Stats card's Top set and
Volume stay "-" for a 0 kg lift, because there is no weight to rank; the runner's own Last time line does say "Top set 0 kg × 9". **Finish and End
no longer fire on one tap**: you are asked first, and after Finish there is a "← Back to workout" at the top of the finish screen. **After a lift
that beats your 1RM estimate the app asks a short question** instead of throwing the whole list at you; "Not now" carries on.

Technical: `app-runner.js` v113 to v116, `app-progress.js` v77 to v78, `app-programs.js` v71 to v72 (the live site has 113, 77, 71). The weight test is
`_hasNumVal` (`app-core.js`, `w != null && w !== ''`) at the runner's ghost placeholder, finish rows, wizard list and Beat strip, and `_xsHasW` /
`_xsSetText` / `_xsSetSpaced` / `_xsSetWithUnit` in `app-progress.js`. A 0 in kg is the number 0 (falsy) and in lb the string "0", which is why a
truthy test failed in one unit and not the other. `confirmEndRunner` is async and re-entry guarded; `skipToNextExercise` asks through it when the
last exercise is finished; `backToRunnerFromFinish` restarts the session timer and draft safety net and uses `_finishToken` so a late PR-lookup repaint
cannot draw the finish screen back over the runner; the typed cardio duration is now escaped on the finish screen and the wizard list. The 1RM
question is `_askAboutNewOneRMs`, which also clears the "Workout saved!" toast (it covered the question's last line on a phone). The decision
entry is `docs/decisions.md`, 2026-10-11.

## Known issues carried into this release

- **Nothing here has been looked at on Jake's phone.** The four 2026-10-11 rows in `docs/bugs/` are `fixed-awaiting-jake`; they close on his
  confirmation. The row "session done on an unscheduled day may not save" stays open: the saved data showed off-day sessions saving fine, the likely
  cause was the 0 kg display bug, and that is for Jake to confirm.
- The runner files a session under the UTC day, not the local day (`docs/bugs/2026-10-04-runner-saves-the-session-date-as-the-utc-day.md`, open).
- Known limits of "Back to workout", named in its bug row: it cancels a running rest timer; an interval block interrupted mid-walk restarts at its
  first phase on "Start timer" and appends its phases again (jumping to another exercise tab and back already does the same); the finish
  screen's notes are kept on Back but are not in the draft, so a page reload loses them.
- From the final review, all outside this release's lines or self-only: `showPostSessionOneRMModal` and the resume modal put `clientId` into an
  `onclick` string without `escapeAttr` (`app-runner.js` 238-239, 3287, 3301; reachable only by hand-editing one's own localStorage draft);
  `app-workouts.js` 3237 shows a toast and then a dialog the same way the 1RM question did (a solo account with assigned clients only); no spec runs
  the 1RM question as solo or as a coach; `checks.sh` rule 9c greps `^function` only, so it cannot see a duplicate `async function` (a manual scan of
  731 top-level names found none); the "ticked sets left out" warning toast is replaced a moment later by "Workout saved!" (the finish screen still
  carries a persistent note).
- Sign out ends every device's session (`docs/bugs/2026-10-03-sign-out-ends-every-device-session.md`, open, awaiting Jake).
- `deploy.yml` actions are pinned by tag, not SHA, and the workflow-level `permissions` also apply to the `check` job; both predate this release.
